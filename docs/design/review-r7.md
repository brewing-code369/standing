## Questions

1. Designed product or styled document? A designed product on all four routes. The line card, the per-code Try it with its receipt inline, and the key rows are built from the content.
2. Primary job obvious in 3 s? On home after load, yes at both widths ("473 complete renewals, each pull inside its cap" then "Three capped keys. One fan signature."). In the first second at 1440 (`r7-1440.png`), the left half is a grey box and a disabled button, so the headline carries the page alone. On `/p/...`, yes now: "Demo membership", the price line, then the key choice. On `/m/...`, "Active", 158 renewals, the next-renewal countdown. The 390 footer then says the runner is down.
3. Would a competent practitioner produce exactly this without the content? No for the line card, refusal codes, receipt and key rows. Yes only for the uppercase-label texture.

## Three highest-leverage fixes

1. Kill the last self-contradictions. In `App.tsx` keep the last good `info` on a failed poll, retry once before flipping, and show "Renewal runner last ticked 40s ago" with an amber dot before ever showing red "not answering". Never contradict a page that is rendering live data. On `/m/...`, make the header count what is pressable: either wire `creator:SpendingLimitExceeded` and the two STANDING codes into `TRY` (`Member.tsx:83`) so it reads "Every refusal on this card can be tried live", or make the text say four. Give the outsider row the chain's real error name instead of a red lowercase "refused", so it matches the line component.
2. Make the home cheat argue the chain's actual reason, and make it work from the first paint. Either have the overcut attack run against a member whose platform key has not yet pulled this period, so "0.38 asked, 0.19 cap, SpendingLimitExceeded" is the true cause, or retitle the receipt "Platform key pulls again after its 0.19 cap is spent" and show "Left this period 0.00" as the red row instead of Asked. Delete the `{false && ...}` block and its `.overshoot` CSS. Set the receipt address in mono with "…". Enable the cheat button as soon as the plan resolves, by picking the member from the plan rather than the ledger. Give the 1440 first viewport a real number-shaped skeleton aligned to the baseline, not a grey slab.
3. One name for the plan and one tier for section heads. Use "Demo membership" plus the price line in the home band and the member subline, matching checkout, and drop one of the two stacked band labels. Bring "Latest renewals" down to the `.h-sec` tier used by "Renewal history" so the hero stays the largest type on home. At 390, shorten the line label to "over the cap" so it holds one line, and get "Use a browser key" under y = 400 by moving the split sentence below the checkout panel header.

## Numbers that look invented

- "1,419 capped pulls settled" (473 × 3) and "1,410" (470 × 3) are still `complete × 3` (`Home.tsx:127`), a derivation worded as a count. Every visible ledger row is 3 OF 3, so it is not wrong in these captures, but it is not read from the chain the way the sentence says. Count the settled `TransferWithMemo` logs or say "three capped pulls per renewal".
- The home receipt "Asked 0.38 / Cap 0.19" in red still implies the excess was the reason. The chain's reason ("already pulled its cap for the period") means 0.00 was allowable. The number is real; the emphasis invents the cause.
- Verified and consistent: 473 × 3 = 1,419; 470 × 3 = 1,410. Member 158 renewals = 158.00 pathUSD at 1.00 each. Member history rows are exactly 5 minutes apart (11:43:56, 11:38:56, 11:33:56 …). The home ledger interleaves three members, each on its own 5-minute cadence (0xEaD1 11:44:10 / 11:39:10, 0x27DB 11:44:04 / 11:39:04, 0xC18a 11:43:56 / 11:38:56). The 0xC18a 11:43:56 row carries hash 0xb550d0…911253 on both `/` and `/m/...`, so the two routes read the same logs. Per-row 0.80 + 0.19 + 0.01 = 1.00. LEFT THIS PERIOD 0.00 of cap matches the fully black bars. Receipt blocks are later than the hero's head block (39,233,798 > 39,233,787 at 1440; 39,233,907 > 39,233,901 at 390). In `member-try-1440.png` the attempt at 11:40:16 shows "in 3m 38s", landing at 11:43:54, which is within 2s of the next history row at 11:43:56. `/new` preview 8.00 / 1.90 / 0.10 = 10.00 at 20% cut, with the 1% fee taken from the platform side, and the footnote states that rule.
